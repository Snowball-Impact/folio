# FOLIO — 커뮤니티 게시판 PRD

**문서 상태:** MVP 확정  
**기능 범위:** Q&A + 자유게시판 + 공지사항 통합  
**목적:** Power BI 사용자 간 질문·경험·노하우 공유와 운영 공지를 하나의 게시판에서 제공  
**원칙:** Simple is Best. 기존 기능을 최대한 재사용하고, 검증되지 않은 기능은 추가하지 않는다.

## 1. 기능 목적

FOLIO 커뮤니티는 별도의 Q&A, 자유게시판, 공지사항을 각각 만들지 않고 하나의 게시판으로 통합한다.

사용자는 Power BI 관련 질문, 팁·노하우, 기타 의견을 자유롭게 작성할 수 있고, 운영자는 동일한 게시판에서 공지를 작성한다.

> **핵심 가설:** FOLIO 사용자는 프로젝트를 보는 것에 그치지 않고, Power BI 관련 질문과 경험을 다른 사용자와 공유할 것인가?

## 2. 서비스 내 역할

```text
Power BI 메뉴
→ 운영자가 수집·큐레이션한 정보 콘텐츠
   ├─ 업데이트 소식
   ├─ 커뮤니티 소식
   ├─ 학습 콘텐츠
   ├─ 자격증
   └─ 공식 레퍼런스

커뮤니티
→ 사용자가 직접 생산하는 콘텐츠
   ├─ 공지
   ├─ 질문
   ├─ 팁·노하우
   └─ 기타
```

`정보공유` 카테고리는 별도로 두지 않는다. 기존 Power BI 콘텐츠 메뉴와 역할이 겹치기 때문이다.

## 3. 정보 구조

```text
커뮤니티
├── 게시글 목록
├── 게시글 상세
│   └── 기존 댓글 기능
└── 게시글 작성·수정
```

별도의 Q&A 화면, 자유게시판 화면, 공지사항 화면을 만들지 않는다.

GNB 메뉴명은 `커뮤니티`로 통일한다.

## 4. 카테고리

| 카테고리 | 목적 | 작성 권한 |
|---|---|---|
| 공지 | 서비스 운영·업데이트 안내 | 관리자 |
| 질문 | Power BI 및 데이터 시각화 관련 질문 | 로그인 회원 |
| 팁·노하우 | 사용 경험, 방법, 실무 노하우 공유 | 로그인 회원 |
| 기타 | 의견, 잡담, 프로젝트 피드백 요청 등 | 로그인 회원 |

- 게시글당 카테고리 1개만 선택한다.
- 일반 사용자는 `공지`를 선택할 수 없다.
- 관리자는 모든 카테고리 작성이 가능하다.
- 실제 게시글이 축적된 후 필요성이 확인되면 카테고리를 조정한다.

## 5. 커뮤니티 목록

상단 구성:

```text
커뮤니티

Power BI 사용자들과 질문과 경험을 나눠보세요.

[전체] [공지] [질문] [팁·노하우] [기타]        [글쓰기]
```

각 게시글에는 다음 정보만 노출한다.

- 카테고리
- 제목
- 작성자
- 작성일
- 댓글 수
- 조회수

정렬 정책:
- 상단 고정 공지를 먼저 노출한다.
- 그 아래 일반 게시글을 최신순으로 정렬한다.
- 인기순, 조회순, 댓글순은 제공하지 않는다.

필터:
`전체 / 공지 / 질문 / 팁·노하우 / 기타`

검색은 MVP에서 제공하지 않는다.

## 6. 글쓰기

로그인한 사용자만 글을 작성할 수 있다.

필수 입력:
1. 카테고리
2. 제목
3. 본문

일반 사용자 선택 가능 카테고리:
`질문 / 팁·노하우 / 기타`

관리자 선택 가능 카테고리:
`공지 / 질문 / 팁·노하우 / 기타`

본문은 일반 Textarea를 사용한다.

MVP 제외:
- Rich Text Editor
- 이미지 첨부
- 파일 첨부
- PBIX 첨부
- 태그
- Embed
- 자동 미리보기

본문에 URL이 존재하는 경우 클릭 가능한 링크로 렌더링한다.

## 7. 게시글 상세

```text
← 커뮤니티

[질문]

Power BI Service 자동 새로고침 관련 질문입니다

맹광국 · 2026.08.23 · 조회 42

────────────────────────────────

Power BI Service에서 Gateway를 연결해서
자동 새로고침을 설정하고 있는데...

────────────────────────────────

댓글 3

[기존 프로젝트 상세 댓글 UI/기능 재사용]
```

게시글 작성자:
- 수정
- 삭제

관리자:
- 수정
- 숨김/삭제
- 공지 관리
- 상단 고정 관리

## 8. 댓글

**커뮤니티용 댓글 시스템을 새로 개발하지 않는다.**

현재 프로젝트 상세페이지에서 사용 중인 댓글 UI·UX, 작성/수정/삭제 정책, 인증 및 권한 정책을 그대로 재사용한다.

권장 구현 개념:

```text
CommentSection(target_type="project", target_id=project_id)
CommentSection(target_type="community_post", target_id=post_id)
```

실제 댓글 DB가 프로젝트에 강하게 종속되어 있다면 현재 구조를 먼저 분석하고 최소 변경으로 확장한다.

반드시 보장:
- 기존 프로젝트 댓글 기능 유지
- 기존 댓글 데이터 손실 없음
- 기존 댓글 정책 하위 호환

## 9. 공지

공지는 별도 기능이나 테이블을 만들지 않고 같은 게시글 구조를 사용한다.

차이:
1. 관리자만 `공지` 카테고리를 작성할 수 있다.
2. 관리자는 공지를 상단 고정할 수 있다.

`is_pinned = true` 공지는 전체 목록과 공지 필터 최상단에 노출한다.

고정 공지는 운영상 최대 3개 수준을 권장하되 MVP에서는 DB 강제 제한까지 만들 필요는 없다.

## 10. 조회수

게시글 상세 진입 시 조회수를 증가시킨다.

기존 프로젝트 상세의 조회수 로직이 있다면 동일 정책과 구현을 우선 재사용한다.

- Streamlit rerun으로 동일 방문에서 반복 증가하지 않도록 한다.
- 복잡한 어뷰징 방지는 하지 않는다.
- 목록과 상세에서 조회수를 표시한다.

## 11. 수정

게시글 작성자는 자신의 게시글을 수정할 수 있다.

수정 가능 항목:
- 카테고리
- 제목
- 본문

일반 사용자는 자신의 게시글을 `공지`로 변경할 수 없다.

수정된 게시글에는 `수정됨`을 표시한다. 수정 이력은 제공하지 않는다.

## 12. 삭제

작성자는 자신의 게시글을 삭제할 수 있다.

관리자는 운영 목적으로 모든 게시글을 삭제 또는 숨김 처리할 수 있다.

가능하면 Soft Delete를 사용한다.

```text
게시글 삭제
→ 목록/상세에서 숨김
→ 연결된 댓글 데이터는 보존
```

게시글 삭제로 기존 댓글이 Cascade Delete되지 않도록 한다.

## 13. URL 처리

본문 URL은 클릭 가능한 링크로 렌더링한다.

MVP 제외:
- Open Graph Preview
- 프로젝트 카드 자동 변환
- iframe Embed
- 자동 썸네일

## 14. 권한

| 기능 | 비회원 | 로그인 회원 | 작성자 | 관리자 |
|---|---:|---:|---:|---:|
| 게시글 목록 조회 | O | O | O | O |
| 게시글 상세 조회 | O | O | O | O |
| 댓글 조회 | O | O | O | O |
| 게시글 작성 | X | O | O | O |
| 본인 게시글 수정 | X | X | O | O |
| 본인 게시글 삭제 | X | X | O | O |
| 댓글 작성/수정/삭제 | 기존 댓글 정책 재사용 | 기존 댓글 정책 재사용 | 기존 댓글 정책 재사용 | 기존 댓글 정책 재사용 |
| 공지 작성 | X | X | X | O |
| 상단 고정 | X | X | X | O |
| 타인 게시글 관리 | X | X | X | O |

권한은 UI뿐 아니라 Supabase RLS에서도 보호한다.

## 15. 비회원 UX

비회원도 게시글 목록, 상세, 댓글을 자유롭게 열람할 수 있다.

`글쓰기` CTA는 노출하되 로그인하지 않은 사용자가 선택하면 기존 FOLIO 로그인 Flow로 연결한다.

## 16. Empty State

전체:
> 아직 작성된 글이 없습니다.  
> Power BI 사용자들과 첫 이야기를 나눠보세요.  
> `[글쓰기]`

질문:
> 아직 등록된 질문이 없습니다.  
> 궁금했던 내용을 가장 먼저 질문해보세요.

팁·노하우:
> 아직 공유된 노하우가 없습니다.  
> 다른 사용자에게 도움이 될 경험을 공유해보세요.

기타:
> 아직 작성된 글이 없습니다.

## 17. 데이터 모델 방향

### community_posts

```text
id
user_id
category
title
content
view_count
is_pinned
created_at
updated_at
deleted_at
```

카테고리 값:

```text
notice
question
tip
other
```

댓글은 신규 테이블을 만들지 않고 기존 댓글 시스템을 재사용하는 것을 우선한다.

## 18. 관리자 페이지 연계

커뮤니티 전용 관리자 페이지를 별도로 만들지 않는다.

향후 통합 Admin에서:

```text
커뮤니티 게시글
├── 목록 조회
├── 상세 확인
├── 수정
├── 숨김/삭제
├── 공지 작성
└── 상단 고정
```

댓글 관리는 기존 댓글 관리 정책과 구현을 재사용한다.

## 19. UI/UX 원칙

- 기존 FOLIO 디자인 시스템을 최대한 유지한다.
- 전통적인 게시판형 목록을 사용한다.
- 프로젝트 갤러리와 같은 카드 중심 UI를 억지로 적용하지 않는다.
- 정보 밀도는 낮게 유지한다.
- 여백을 충분히 사용한다.
- 카테고리는 Badge 형태로 명확하게 구분한다.
- `글쓰기` 등 핵심 CTA만 강조한다.
- 초기 데이터가 적어도 어색하지 않도록 Empty State를 제공한다.
- 모바일에서는 카테고리 필터가 자연스럽게 줄바꿈 또는 가로 스크롤될 수 있도록 한다.

## 22. Acceptance Criteria

```text
비회원
→ 커뮤니티 목록 조회
→ 게시글 상세 조회
→ 댓글 조회

로그인 회원
→ 글쓰기
→ 질문 / 팁·노하우 / 기타 선택
→ 게시글 등록
→ 다른 회원이 기존 댓글 기능으로 댓글 작성
→ 작성자가 게시글 수정/삭제

관리자
→ 공지 작성
→ 상단 고정
→ 부적절한 게시글 숨김/삭제
```

추가 완료 조건:
- 카테고리 필터 정상 동작
- 일반 사용자는 공지 작성 불가
- 고정 공지가 일반 글보다 우선 노출
- 조회수가 Streamlit rerun으로 비정상 증가하지 않음
- 본문 URL 클릭 가능
- 기존 프로젝트 댓글 기능과 데이터에 회귀 문제 없음
- Supabase RLS가 게시글 권한 보호

## 23. MVP 핵심 정의

> **FOLIO 커뮤니티는 공지, 질문, 팁·노하우, 기타 글을 하나의 게시판에서 공유하고 기존 댓글 기능으로 대화하는 공간이다.**

이번 단계에서는 게시판을 더 세분화하지 않고, 실제 사용자 활동이 발생하는지부터 검증한다.
