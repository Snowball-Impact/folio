## Backlog Item 1: 비밀번호 찾기 및 재설정 플로우 개선

- 화면: main / Login

- 우선순위: A(중요)
- 광국 의견: 좋아요

### 요구사항

## Backlog Item 2: 헤더 네비게이션 메뉴 전체 노출

Labels: `backlog`, `ux`, `priority:A`, `area:main`

### 기능정의서
- no. 2
- 분류: UX/UI
- 화면: main
- 기능: 카테고리 기능
- 우선순위: A(중요)
- 광국 의견: 네비게이션 메뉴 개선에 동의. Streamlit 기본 컴포넌트 디자인 한계가 있어 재시도 필요.

### 정리
- 기능정의서의 "카테고리"는 콘텐츠 카테고리가 아니라 헤더 네비게이션 메뉴를 의미한다.
- 햄버거 아이콘 대신 주요 메뉴를 헤더에 직접 노출한다.
- 기존 FOLIO 디자인 톤과 Streamlit 제약을 고려해 데스크톱/모바일 모두 자연스럽게 동작해야 한다.

### 완료 기준
- 데스크톱에서 주요 네비게이션이 헤더에 바로 보인다.
- 모바일에서는 좁은 화면에서도 메뉴가 깨지지 않는다.
- 현재 활성 페이지 상태가 명확히 표시된다.

## Backlog Item 9: 댓글 기능 1차 구현

Labels: `backlog`, `feature`, `priority:A`, `area:content`

### 기능정의서
- no. 9
- 분류: Feature
- 화면: Content Page
- 기능: 댓글 기능
- 우선순위: A(중요)
- 광국 의견: 최고 중요한 기능

### 범위
- 1차 구현은 구조화 피드백이 아니라 단순 댓글과 1단계 대댓글로 진행한다.
- 목적은 댓글 기능 자체의 완성도가 아니라 프로젝트에 실제 반응과 대화가 발생하는지 빠르게 실증하는 것이다.
- 피드백 유형, 작성자 질문, 알림, 관리자 댓글 관리는 후속으로 분리한다.

### 요구사항
- 로그인 사용자가 프로젝트 상세 페이지에 댓글을 작성할 수 있다.
- 댓글 목록은 최신순 또는 맥락에 맞는 정렬로 표시한다.
- 작성자는 본인 댓글을 삭제할 수 있다.
- 로그인 사용자는 기존 댓글에 1단계 대댓글을 작성할 수 있다.
- 프로젝트 작성자의 댓글과 대댓글에는 작성자 배지를 표시한다.
- 프로젝트 카드와 상세 메타에 댓글 수를 표시한다.

### 완료 기준
- 상세 페이지에서 댓글 작성/조회/삭제가 가능하다.
- 상세 페이지에서 1단계 대댓글 작성/조회/삭제가 가능하다.
- RLS 또는 서비스 레이어에서 권한이 보호된다.
- 댓글 관련 테스트가 추가된다.
