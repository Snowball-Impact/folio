# FOLIO PRD v2.0

## 데이터 시각화 프로젝트 발견·경험·토론 커뮤니티

- 문서 버전: v2.0
- 제품 단계: MVP 전환
- 작성일: 2026-08
- 제품명: FOLIO
- 초기 콘텐츠 범위: 공개 데이터 시각화 프로젝트
- 장기 확장 범위: 데이터·AI·웹 서비스 프로젝트

---

## 1. 제품 개요

FOLIO는 우수한 데이터 시각화 프로젝트를 발견하고, 직접 경험하며, 다른 사람들과 의견을 나눌 수 있는 콘텐츠 기반 커뮤니티다.

초기에는 사용자의 자발적인 프로젝트 등록에 의존하지 않는다. Tableau Public, Streamlit 등 공개 갤러리에서 활용 가능한 프로젝트를 운영자가 선별하여 FOLIO 콘텐츠로 제공한다.

사용자는 콘텐츠를 보기 위해 FOLIO에 방문하고, 댓글과 공유 등의 활동을 통해 커뮤니티에 참여한다. 충분한 콘텐츠와 이용자가 확보되면 프로젝트 등록 요청과 직접 등록 기능을 단계적으로 개방한다.

한 줄 정의:

> 좋은 데이터 시각화 프로젝트를 발견하고, 직접 경험하고, 함께 이야기하는 커뮤니티

---

## 2. 비전

> AI 시대에도 사람의 질문과 해석은 중요한 자산이다.

하나의 데이터 시각화에서도 사람마다 서로 다른 질문과 인사이트를 발견할 수 있다. FOLIO는 프로젝트 자체만 수집하는 것이 아니라, 프로젝트를 본 사람들이 남긴 질문, 해석, 경험과 의견을 함께 축적한다.

장기적으로 데이터 시각화에서 시작하여 AI 서비스와 웹 서비스 프로젝트까지 확장한다.

---

## 3. 현재 문제

### 초기 콘텐츠 확보가 어렵다

신규 플랫폼에는 사용자와 콘텐츠가 부족하기 때문에, 사용자가 먼저 자신의 프로젝트를 등록할 이유가 약하다.

```text
콘텐츠 부족
-> 방문자 부족
-> 댓글과 반응 부족
-> 프로젝트 등록 동기 부족
-> 콘텐츠 부족
```

### 공개 프로젝트는 여러 플랫폼에 흩어져 있다

좋은 데이터 시각화 프로젝트가 Tableau Public, Streamlit, Power BI Community 등 여러 플랫폼에 분산되어 있다. 사용자는 각 플랫폼을 직접 탐색해야 하며, 프로젝트를 주제와 문제 중심으로 비교하거나 발견하기 어렵다.

### 기존 갤러리는 목록 제공에 집중한다

기존 플랫폼은 프로젝트의 실행 환경과 기본 정보는 제공하지만 한국어 기반 설명, 프로젝트의 문제와 목적, 사용 데이터, 주요 분석 내용, 사용자 관점의 해석, 댓글과 토론, 플랫폼 통합 탐색은 상대적으로 부족하다.

### 임베드 가능 여부가 플랫폼마다 다르다

Tableau Public, Streamlit, Hugging Face 등은 플랫폼과 프로젝트 설정에 따라 iframe 삽입 가능 여부가 다르다. 모든 프로젝트를 FOLIO 내부에서 직접 실행할 수 있다고 가정하면 안 된다.

---

## 4. 제품 전략

FOLIO는 장기적으로 데이터·AI·웹 프로젝트를 공유하고 경험하는 플랫폼을 지향한다. MVP에서는 콘텐츠 수급과 시각적 소비가 용이한 데이터 시각화 프로젝트에 집중한다.

초기 지원 플랫폼 우선순위:

1. Tableau Public
2. Streamlit
3. Power BI 공개 프로젝트
4. 필요 시 Looker Studio 등 추가

플랫폼 수를 한 번에 늘리지 않는다. 각 플랫폼에서 콘텐츠 수집, 썸네일 확보, 임베드와 외부 링크 처리 방식이 안정화된 후 다음 플랫폼을 추가한다.

---

## 5. 핵심 제품 가설

1. 콘텐츠 소비: 사용자는 흥미로운 주제의 데이터 시각화 프로젝트를 발견하고 직접 체험하기 위해 FOLIO를 방문할 것이다.
2. 콘텐츠 재가공: 프로젝트의 문제, 데이터, 분석 내용과 핵심 포인트를 간결하게 정리하면 원본 갤러리보다 프로젝트를 이해하기 쉬워질 것이다.
3. 커뮤니티: 프로젝트를 본 일부 사용자는 댓글로 질문, 해석 또는 경험을 남길 것이다.
4. 공급 전환: 충분한 콘텐츠와 반응이 축적되면 프로젝트 제작자는 자신의 프로젝트를 FOLIO에 등록하거나 기존 콘텐츠의 소유권을 요청할 것이다.

장기 가설:

> 데이터 프로젝트와 사람들의 해석이 함께 축적되면 FOLIO는 프로젝트 갤러리를 넘어 집단지성 기반의 지식 플랫폼으로 발전할 수 있다.

---

## 6. 핵심 사용자

### 콘텐츠 탐색자

데이터 시각화 사례와 아이디어를 찾는 사용자다. 좋은 프로젝트 발견, 시각화 레퍼런스 탐색, 실제 대시보드와 앱 체험, 분석 주제와 아이디어 획득, 다른 사용자의 의견 확인이 주요 목적이다.

### 학습자·취업 준비생

데이터 분석과 시각화를 공부하거나 포트폴리오를 준비하는 사용자다. 우수 사례 학습, 프로젝트 구성 방식 참고, 도구별 구현 사례 확인, 자신의 프로젝트 주제 탐색, 다른 사람의 피드백과 질문 학습이 주요 목적이다.

### 프로젝트 제작자

Tableau, Streamlit, Power BI 등으로 프로젝트를 만든 사용자다. 자신의 프로젝트 노출, 외부 반응 확인, 프로젝트 유입 증가, 질문과 의견 확인, 개인 포트폴리오 활용이 주요 목적이다.

## 7. MVP 목표

MVP는 플랫폼의 모든 기능을 구현하는 것이 아니라 다음 세 가지를 검증한다.

1. 콘텐츠 공급: 운영자가 공개 데이터 시각화 프로젝트를 지속적으로 확보하고 게시할 수 있는가?
2. 콘텐츠 소비: 사용자가 갤러리에서 프로젝트를 발견하고 상세 페이지와 실제 프로젝트를 확인하는가?
3. 커뮤니티 반응: 사용자가 프로젝트에 댓글을 남기고 다른 사람의 댓글을 읽는가?

## 8. 콘텐츠 운영 원칙

### 자동 생성보다 수집·가공을 우선한다

FOLIO는 존재하지 않는 프로젝트를 AI로 생성하지 않는다.

```text
공개 프로젝트 발견
-> 원본 정보 수집
-> 운영자 검토
-> 설명과 메타데이터 가공
-> FOLIO 게시
```

AI는 원문 번역, 설명 초안 작성, 카테고리 추천, 태그 추천, 긴 README 요약을 보조할 수 있지만 모든 콘텐츠는 게시 전 운영자가 검토한다.

### 원본과 제작자를 명확히 표시한다

각 콘텐츠에는 프로젝트 원본 제목, 원작자 또는 게시자, 원본 플랫폼, 원본 프로젝트 URL, GitHub URL, FOLIO 편집·요약 콘텐츠임을 알리는 표시를 제공한다.

### 콘텐츠 전체를 복제하지 않는다

FOLIO는 원본 프로젝트의 코드, 데이터, 보고서를 무단 복제하지 않는다. 대표 이미지, 프로젝트 소개, 출처와 링크, 임베드 가능한 실행 화면, FOLIO 사용자 댓글을 제공한다.

### 임베드 실패를 정상 상태로 취급한다

프로젝트 상태는 `embed_supported`, `external_link_only`, `embed_failed`로 구분한다. 임베드가 불가능한 경우 대표 이미지, 간략한 설명, 원본에서 실행하기 버튼, GitHub 또는 관련 링크, 댓글을 제공한다.

## 9. 초기 콘텐츠 소스 전략

### 1차 소스: Tableau Public

선정 이유:

- 공개 데이터 시각화 콘텐츠가 풍부함
- 공유 코드에 뷰 이름과 정적 이미지 URL이 포함되는 경우가 많음
- 주제별 시각화 프로젝트를 확보하기 쉬움
- 인터랙티브 시각화 중심으로 FOLIO 초기 정체성과 부합함

수집 정보:

- 프로젝트 제목
- 제작자
- Tableau 뷰 URL
- iframe URL
- 정적 이미지 URL
- 설명
- 태그 또는 카테고리
- 공개일 또는 수집일

### 2차 소스: Streamlit

선정 이유:

- 데이터 분석과 AI 웹 앱이 다양함
- 실제 서비스를 직접 체험할 수 있음
- 향후 웹 서비스 프로젝트 확장과 연결됨

주의사항:

- `share.streamlit.io`가 아닌 최종 `*.streamlit.app` 주소 사용
- 임베드 URL에는 `?embed=true` 적용
- 앱 공개 여부, 절전 상태, 인증 구조에 따라 임베드 실패 가능
- 임베드 실패 시 외부 링크 방식 사용

### Power BI

Power BI는 공개 링크 확보와 게시 권한에 제약이 있으므로 초기 핵심 수집원으로 사용하지 않는다. 공개적으로 정상 접근 가능한 프로젝트 또는 사용자가 직접 등록 요청한 프로젝트부터 제한적으로 지원한다.

## 10. 콘텐츠 선정 기준

필수 기준:

- 원본에 공개적으로 접근할 수 있음
- 프로젝트의 목적 또는 주제를 파악할 수 있음
- 대표 화면을 확보할 수 있음
- 출처와 제작자를 확인할 수 있음
- 개인정보 또는 민감정보 문제가 없음

품질 기준:

- 흥미로운 질문을 다룸
- 데이터 시각화가 이해하기 쉬움
- 인터랙션을 통해 추가 탐색이 가능함
- 학습 또는 실무 참고 가치가 있음
- FOLIO 사용자에게 토론 소재를 제공함

제외 기준:

- 출처 또는 제작자가 불분명함
- 접속이 불가능하거나 지속적으로 오류가 발생함
- 단순 템플릿 또는 중복 콘텐츠
- 저작권과 개인정보 위험이 있음
- 광고 또는 홍보 목적만 강한 콘텐츠
- 설명 없이 시각화만 존재하여 맥락 파악이 어려움

## 12. 콘텐츠 상세 구조

각 프로젝트 상세 페이지는 다음 순서를 따른다.

```text
Hero
-> Project Preview
-> Project Summary
-> Data & Analysis
-> Source & Links
-> Comments
```

### Hero

대표 이미지, 프로젝트 제목, 한 줄 소개, 원작자, 원본 플랫폼, 주제 카테고리, 원본에서 보기 버튼을 제공한다.

### Project Preview

임베드 가능 프로젝트는 iframe으로 표시하고 전체화면 또는 새 창 실행 버튼을 제공한다. 임베드 불가능 프로젝트는 대표 이미지, 외부에서 실행하기 버튼, 임베드할 수 없는 프로젝트라는 안내를 제공한다.

### Project Summary

초기 상세 구조는 네 항목으로 통일한다.

- 문제 정의: 이 프로젝트가 다루는 질문 또는 문제는 무엇인가?
- 사용 데이터: 어떤 데이터가 사용되었는가?
- 분석 및 시각화: 어떤 방식으로 분석하고 표현했는가?
- 주요 관찰 포인트: 사용자가 프로젝트를 볼 때 주목하면 좋은 내용은 무엇인가?

원작자가 직접 작성하지 않은 콘텐츠에는 다음 표시를 붙인다.

> 본 설명은 공개된 프로젝트 정보를 기반으로 FOLIO가 편집한 소개입니다.

### Source & Links

원본 프로젝트, 제작자 프로필, GitHub, 데이터 출처, 관련 보고서를 제공한다.

### Comments

일반 댓글 작성, 댓글 수정 및 삭제, 1단계 답글, 작성 시간, 작성자 표시, 새 댓글 및 답글 알림을 제공한다. 구조화 댓글은 일반 댓글 데이터를 확인한 후 도입한다.

## 14. 프로젝트 카드

갤러리 카드에는 대표 이미지, 프로젝트 제목, 한 줄 설명, 주제 카테고리, 플랫폼, 제작자, 댓글 수를 표시한다.

사용자는 카드만 보고 다음을 이해할 수 있어야 한다.

- 무엇을 다루는 프로젝트인가?
- 어떤 형태의 콘텐츠인가?

## 20. MVP 성공 기준

다음 행동이 반복적으로 발생하면 초기 가설이 유효하다고 판단한다.

1. 운영자가 지속 가능한 비용으로 프로젝트를 공급한다.
2. 사용자가 갤러리에서 프로젝트 상세로 이동한다.
3. 사용자가 실제 프로젝트를 실행하거나 원본 링크를 선택한다.
4. 일부 프로젝트에서 댓글과 답글이 발생한다.
5. 외부 제작자가 자신의 프로젝트 등록을 요청한다.

재검토 조건:

- 콘텐츠 게시 비용이 지나치게 높다.
- 프로젝트 상세 조회는 있으나 실행 클릭이 발생하지 않는다.
- FOLIO 설명이 원본 프로젝트보다 추가적인 가치를 제공하지 못한다.
- 댓글과 재방문이 거의 발생하지 않는다.
- 프로젝트 출처와 저작권 관리 부담이 지나치게 크다.
- 자동 수집 없이는 콘텐츠 공급을 유지할 수 없다.

## 23. 제품 원칙

- Content First: 사용자 등록 기능보다 사람들이 실제로 보고 싶은 콘텐츠를 먼저 확보한다.
- Curated, Not Copied: 원본을 복제하지 않고 출처를 명확히 표시한 편집·큐레이션 콘텐츠를 제공한다.
- Experience Before Explanation: 긴 설명보다 프로젝트의 대표 화면과 실행 경험을 먼저 보여준다.
- Topic Before Tool: Power BI나 Tableau보다 프로젝트가 다루는 문제와 주제를 우선한다.
- Fallback by Design: 임베드 실패를 예외가 아니라 정상적인 제품 상태로 설계한다.
- Manual Before Automation: 수동 운영으로 가치와 반복 업무를 확인한 후 자동화한다.
- Community After Consumption: 먼저 볼 만한 콘텐츠를 제공하고, 그 위에 댓글과 제작자 참여를 구축한다.

## 24. 최종 MVP 정의

> FOLIO MVP는 공개된 우수 데이터 시각화 프로젝트를 선별해 소개하고, 사용자가 프로젝트를 직접 경험한 뒤 의견을 나눌 수 있도록 하는 콘텐츠 기반 커뮤니티다.

장기적으로 데이터·AI·웹 서비스 프로젝트 플랫폼을 지향하지만, 현재는 콘텐츠 수급과 사용자 소비 행동을 검증하기 위해 Tableau Public과 Streamlit을 중심으로 시작한다.

이번 단계의 우선순위:

1. 볼 만한 콘텐츠를 확보한다.
2. 프로젝트를 이해하고 실행하기 쉽게 가공한다.
3. 임베드 여부와 관계없이 일관된 상세 경험을 제공한다.
4. 댓글과 등록 요청을 통해 커뮤니티 및 제작자 참여 가능성을 확인한다.
5. 검증된 운영 업무만 점진적으로 자동화한다.
