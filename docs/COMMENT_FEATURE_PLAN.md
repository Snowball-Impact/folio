# 댓글 기능 기획서

상태: 1차 MVP, 미확인 댓글 배지, 댓글 알림 1차 구현 완료 (2026-08-02)

## 1. 목표

프로젝트 상세 페이지에 댓글 기능을 추가해, 사용자가 프로젝트에 대한 의견·질문·응답을 남길 수 있도록 한다.

## 2. 1차 MVP 범위

다음 기능만 우선 구현한다.

- 프로젝트 상세 페이지 댓글 조회
- 댓글 작성
- 대댓글 작성(1단계)
- 본인 댓글/대댓글 삭제
- 프로젝트 작성자 배지
- 프로젝트 카드와 상세 메타의 댓글 수 표시
- 마이페이지 미확인 댓글 `NEW` 배지
- 댓글 작성 시 프로젝트 작성자에게 알림 생성
- 헤더 알림 배지와 최근 알림 popover, 전체 알림 페이지
- 설정된 경우 프로젝트 작성자에게 댓글 이메일 알림 발송

다음 기능은 1차 범위에서 제외한다.

- 댓글 수정
- 댓글 좋아요/추천
- 대댓글의 대댓글
- 작성자 권한 기반 moderation

## 3. 사용자 경험

### 3.1 화면 배치

- 상세 페이지 하단에 댓글 섹션을 별도 카드로 배치한다.
- 상단에는 “댓글 N개” 제목과 요약 안내를 표시한다.
- 작성 폼은 섹션 상단 또는 바로 아래에 배치한다.
- 댓글 목록은 아래에 표시한다.
- 페이지 하단의 기존 돌아가기 버튼은 댓글 섹션 아래에 배치한다.

### 3.2 댓글 작성 흐름

- 로그인한 사용자만 작성 가능하다.
- 비로그인 사용자는 작성 폼 대신 로그인 유도 문구를 보여준다.
- 전송 버튼은 항상 활성 상태로 둔다. 입력값이 비어 있으면 클릭 후 안내 메시지를 보여준다.

### 3.3 대댓글 흐름

- 각 댓글 아래에 “답글 달기” 버튼을 제공한다.
- 클릭 시 해당 댓글 아래에 인라인 입력창이 열린다.
- 대댓글은 부모 댓글보다 한 단계 들여쓰기해서 표시한다.
- 대댓글의 대댓글은 지원하지 않는다.

### 3.4 삭제 흐름

- 본인 댓글/대댓글에만 삭제 버튼을 노출한다.
- 삭제 후 목록을 다시 불러오거나 rerun으로 반영한다.

### 3.5 댓글 수와 작성자 표시

- 프로젝트 카드에는 조회수, 좋아요 수와 함께 댓글 수를 표시한다.
- 프로젝트 상세 히어로 액션 그룹에도 댓글 수를 표시한다.
- 프로젝트 작성자의 댓글과 대댓글에는 “작성자” 배지를 표시한다.

## 4. 데이터 설계

댓글은 하나의 테이블로 관리한다.

### 4.1 댓글 테이블 예시

- id: uuid
- project_id: uuid
- author_id: uuid
- parent_id: uuid|null
- body: text
- depth: integer
- is_deleted: boolean
- created_at: timestamptz
- updated_at: timestamptz

### 4.2 규칙

- `parent_id`가 null이면 최상위 댓글이다.
- `parent_id`가 있으면 대댓글이다.
- `depth`는 0(댓글), 1(대댓글)로 제한한다.
- 대댓글의 대댓글은 지원하지 않는다.

### 4.3 미확인 댓글 읽음 상태

- `project_comment_reads`는 프로젝트 작성자별 마지막 댓글 확인 시각을 저장한다.
- 마이페이지 `NEW` 배지는 본인이 아닌 사용자가 남긴 댓글 중 마지막 확인 시각보다 최신 댓글이 있을 때만 표시한다.
- 프로젝트 작성자가 상세 댓글 섹션을 보면 해당 프로젝트의 `last_read_at`을 갱신한다.

## 5. 권한 및 보안

- 공개 프로젝트의 댓글은 조회 가능하다.
- 비공개 프로젝트 댓글은 프로젝트 작성자만 프로젝트 상세와 함께 조회할 수 있다.
- 로그인 사용자만 댓글/대댓글 작성 가능하다.
- 본인 댓글/대댓글만 삭제 가능하다.
- RLS를 통해 서버 측 권한을 보장한다.

## 8. 완료 기준

다음 조건을 만족하면 1차 구현으로 간주한다.

- 프로젝트 상세 페이지에서 댓글을 확인할 수 있다.
- 로그인한 사용자가 댓글과 대댓글을 작성할 수 있다.
- 본인 댓글/대댓글을 삭제할 수 있다.
- 비로그인 사용자는 작성만 막고 조회는 가능하다.
- 프로젝트 작성자 배지와 댓글 수가 카드/상세에 표시된다.

## 9. 구현 결과

- 상세 페이지 하단에 댓글 섹션을 별도 컨테이너로 렌더링한다.
- 로그인 사용자는 댓글과 최상위 댓글에 대한 1단계 답글을 작성할 수 있다.
- 댓글/답글 전송 버튼은 항상 활성 상태이며, 빈 입력은 댓글 영역 안에서 안내 메시지로 처리한다.
- 본인 댓글은 삭제할 수 있고, 삭제 전 확인 단계를 둔다.
- 댓글과 답글은 한 줄 압축 레이아웃으로 표시하고, 답글은 배경색과 들여쓰기로 구분한다.
- 댓글 목록은 루트 댓글 기준 20개 단위 페이지네이션을 사용하며, 한 페이지뿐이어도 중앙에 현재 페이지 번호를 표시한다.
- 프로젝트 카드, 마이페이지 카드, 상세 히어로 액션 그룹에 댓글 수를 표시한다.
- 마이페이지 내 프로젝트 카드에는 안 본 외부 댓글이 있으면 제목 옆에 `NEW` 배지를 표시한다.
- 홈갤러리 프로젝트 카드는 최근 7일 내 등록이면 우상단에 `NEW`, 오래된 프로젝트에 최근 7일 내 댓글이 달렸으면 `댓글 NEW`를 표시한다.
- 댓글 작성자는 프로젝트 작성자에게 댓글 알림을 생성한다. 본인 프로젝트에 본인이 남긴 댓글은 알림을 만들지 않는다.
- 로그인 사용자의 헤더에는 종 아이콘 알림 버튼을 표시하고, 읽지 않은 알림이 있으면 빨간 `N` 배지를 붙인다.
- 알림 버튼을 누르면 최근 알림 popover를 보여준다. popover를 여는 것만으로는 읽음 처리하지 않고, 알림별 `보기`나 `모두 읽음`에서 읽음 처리한다.
- 전체 알림 페이지는 유지한다. 알림 페이지에 들어가면 최근 알림을 보여주고 새 알림은 읽음 처리한다.
- 이메일 알림은 `SUPABASE_SERVICE_ROLE_KEY`와 SMTP 설정이 모두 있을 때만 발송한다. 설정이 없거나 발송이 실패해도 댓글 작성과 앱 내부 알림 생성은 유지한다.
- 댓글 등록 응답이 SMTP 발송을 기다리지 않도록 이메일은 백그라운드 스레드에서 발송한다.
- 같은 댓글에 대한 알림이 중복 생성되지 않도록 `notifications_project_comment_unique_idx` unique index를 둔다.
- 댓글 작성/삭제 후 댓글 수 캐시를 비운다.
