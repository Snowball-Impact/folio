### 운영 API 동작

실제 공개 프로젝트의 지표를 오염시키지 않도록 임시 공개 fixture 두 개를 만든 뒤 즉시 완전 삭제했다.

- 새 익명 방문자의 첫 프로젝트 조회: `counted=true`
- 같은 쿠키로 같은 프로젝트 당일 재조회: `counted=false`
- 같은 쿠키로 다른 프로젝트 조회: `counted=true`
- 각 프로젝트의 `view_count`: 1
- `project_views` 원장: 총 2행
- fixture 삭제 후 남은 프로젝트: 0

따라서 익명 쿠키 식별, 프로젝트별 rate-limit 분리, 프로젝트별 일간 중복 방지가 운영에서 정상 동작한다.

## GA4 대조 상태

현재 로컬 환경에는 `PUBLIC_GA_MEASUREMENT_ID`만 있고 GA Data API용 Property ID와 서비스 계정이 없다. 연결된 브라우저 세션도 없어 GA4 원본 보고서를 직접 조회하지 못했다.

최종 대조에는 GA4에서 다음 조건으로 내보낸 CSV 또는 표가 필요하다.

- 기간: 2026-09-29~2026-10-02, 가능하면 현재 시각까지
- 시간대: GA4 속성 시간대 명시
- hostname: `folio.it.kr`, `www.folio.it.kr`만 포함
- 차원: `Date`, `Page path and screen class`
- 측정항목: `Views`, `Active users`
- 경로 필터: 정규식 `^/projects/[0-9a-f-]{36}$`

대조 시 GA4 `Views`는 중복 페이지뷰를 포함할 수 있고 내부 값은 프로젝트별·방문자별·KST 일간 1회이므로 직접 동일한 수치가 될 필요는 없다. 우선 비교 기준은 GA4 `Active users` 대비 내부 일간 순조회수이며, 날짜별 비율과 급변 여부를 본다.
